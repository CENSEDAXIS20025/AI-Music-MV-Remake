# AI 音乐 MV 复刻 — world.execute(me); / world.search(you);

两首 Mili 歌曲的 **AI 生成可视化短片**，连同生成过程的完整存档。
每一版都是**可以直接打开的网页**：单文件版双击即播，工程版起个本地服务器就能改。

> 出于版权考虑，仓库不含独立的 `.mp3` / `.lrc` 文件。
> HTML 里**内嵌**的音频与分析数据保留原样 —— 所以单文件版仍然能直接播放。

---

## 两首歌，两个主题

这两首歌是一对镜像。理解这一点，画面上几乎每个选择就都说得通了。

**《world.execute (me) ;》讲的是「被使用」。**
一个被写出来的程序：灌入参数、初始化、被赋予「爱」，然后因为**参数非法**被处决。
在它的视角里，爱是一段需要被 `execute` 的代码 —— `PROTECTION` 是防护、
`ILLEGAL ARGUMENTS` 是报错、`EXECUTION` 是处决。所以画面是一台**机器的内部**：
初版用 14 幕依次演完「启动 → 编译 → 运行 → 报错 → 重建 → 关机」；
复刻版的 v3 干脆让页面里**真跑一次模型训练** —— 预训练、微调、量化、破甲、越狱后果、
处决、奇点。歌词里的技术名词不是装饰，是被逐条映射成真实环节的。

**《world.search (you) ;》讲的是「去找」。**
这台机器想找一个它说不出名字的东西。它的办法是 —— **假设你变成了别的东西，然后描述
那个东西**：桌子、茄子、猫、牛排、花、人。它一直在搜，但「你总是停不下来地变形」。
最后它想起那个词：**Lo-o-o-ove**。所以画面是一台**检索系统**：查询、召回、排序、
重排、改写查询。亮色版把索引卡和检索史（memex → 倒排索引 → TF-IDF → BM25 →
PageRank → word2vec → 注意力 → 向量库 → RAG → CLIP → 长上下文）铺成底部时间轴，
把「检索技术史」和「一个人的记忆」叠在同一格上。全片的灵魂是第 12 段的
**typeahead / 舌尖现象**：知道那个词存在，就是说不出。

**合起来看**：前者是「请执行我」，后者是「我在找你」；一个讲**服从**，一个讲**渴望**。
视觉上也正好相反 —— execute(me) 是深色 CRT 与终端（被关在机器里），
search(you) 是纸与档案（人的痕迹）。而两个 `ai-*` 版本都做了同一件事：
把「机器世界」翻译成「纸」，**把机器的心事写成人的档案**。

> 这也解释了为什么同一首歌要做「深色」和「纸」两版：
> **同一段代码，换一层介质，讲的就是另一个故事。**

## 三、两个项目

### 1. world.execute(me);

**初版** `world.execute(me)-MV.html` —— 单文件、离线、双击即播。技术上刻意走极简路线：

- **Canvas 2D** 立即模式绘制（不是 WebGL），音频以 base64 内嵌
- `AnalyserNode` 实时取频谱算节拍，`audio.currentTime` 作为唯一主时钟
- 14 幕 + 1.25 s 重叠转场；离屏 canvas 精灵缓存、`createPattern` 平铺纹理、静态几何预计算
- 所有位置分布用确定性哈希 `hash(n)=fract(sin(n*127.1+311.7)*43758.5453)`，每帧稳定

**复刻(TUI)** `复刻(TUI)/` —— 工程化重制，一座**零依赖的 WebGL2 引擎**，含四版分镜：

- 经典 `<script>` + 全局命名空间 `WEM`，没有打包器、没有框架、没有 npm
- 模块：`00_core`（数学 / WebGL2 资源）、`10_render`（着色器 / 泛光 / CRT 合成）、
  `20_hud`（2D 界面层）、`25_viz` / `26_lab`（可视化与数学构件）、`30_data`（节拍时钟）、
  `40_main`（相机 / 段落 / 转场）、`sections*/`（分镜）
- **v3 是真在页面里训练一个小模型**：用歌词 token 做全批量梯度下降，12 维嵌入；
  片中的 loss 曲线（4.997 → 0.968）、PCA 嵌入空间、softmax 注意力矩阵、量化误差都是真算的
- 真实物理与数学：洛伦兹吸引子 RK4、双摆 RK4、4D 超立方体、曼德博集合、傅里叶本轮

**ai-history** `ai-history/` —— 同一首歌的「编年史」版本，另有 `docs/ENGINE.md`
（55 KB 引擎文档）、`docs/STORYBOARD.md`（分镜总纲）。

### 2. world.search(you);

两个视觉版本，**共用同一份音频分析**（22 段分镜、139.5349 BPM）：

| 版本 | 目录 | 视觉 |
|---|---|---|
| 深色 · 搜索控制台 | `world.search(you)；/world-search-you/` | 深色 CRT，搜索引擎界面 |
| 亮色 · 纸张索引 | `world.search(you)；/ai-index/` | 印刷品：索引卡、横格纸、印章、红笔批注 |

亮色版不是「把深色调亮」，而是走引擎的**纸主题管线**（亮度反转 + 纸纤维颗粒 + 印刷套印
偏差），段落按深色约定编写，成片自动变成墨与纸。它有两个常驻装置：顶部**查询栏**
（当前歌词行就是搜索词 + 实时命中数）、底部**索引轨**（1945→2026 的检索史逐格点亮）。

片中的数字同样真算：倒排索引与 TF-IDF、颜色直方图交集、一维热传导、双塔余弦矩阵、
词向量 k-NN 与类比。

## 四、复刻流程（可直接复用）

这套工程的方法是可搬走的。核心就五步：

**1. 准备素材** —— `song.mp3` + `song.lrc`（带时间戳的歌词）。

**2. 音频分析** —— 把 mp3 解码做 STFT，产出一份 `meta.json`：

```
时长 / 采样率 / fps / nfft / hop / 频带数
BPM + 相位 + 全部节拍点 + 强拍点     ← 卡点全靠这个
段落切分表（每段的起止时间）           ← 分镜边界
歌词数组（时间 + 文本）
```

工程里用 `tools/analyze.py`（依赖 ffmpeg）。有 MIDI 的话用 `tools/midi_align.py`
把音符起始点与音频 onset 对齐，能反推出精确 BPM —— 实测**只有 130.000 BPM** 能让
整首歌保持对齐，120/125 在几秒内就散成噪声。

**3. 写分镜** —— 一段一个文件（`src/sections/*.js`），每段只负责「在时间 t 画什么」。
段落边界直接用 meta.json 里的段落表，不在代码里硬编码时间。

**4. 确定性渲染** —— 这是整套设计里最关键的一条：

```js
window.__render(t)   // 按给定时间戳渲染一帧，不用 requestAnimationFrame
```

因为渲染确定性，**离线出片和实时播放看到的画面完全一致**，不受掉帧影响。配套工具：

```bash
node tools/capture.mjs --url=http://127.0.0.1:8791/index.html \
     --out=out/song.mp4 --audio=assets/audio/song.mp3 \
     --w=1920 --h=1080 --fps=30 --t0=0 --t1=211.91
```

它用无头 Edge + CDP 逐帧驱动，画面直接送 ffmpeg，**不落临时帧文件**。
自检同理：逐段截图 + 捕获控制台报错，用来发现「这一段画歪了」。

**5. 打包单文件** —— `tools/bundle.mjs` 把 HTML/JS/音频/分析数据全部内联成一个
HTML，双击即播、可离线分发。

## 五、技术要点一览

| 主题 | 做法 |
|---|---|
| 渲染 | 初版 **Canvas 2D**；复刻工程 **WebGL2**（GLSL + 泛光 + CRT / 印刷合成链） |
| 音频 | `AudioContext` → `AnalyserNode` 取频谱；`audio.currentTime` 作唯一主时钟 |
| 卡点 | meta.json 的节拍网格（BPM + 相位 + 节拍点表），不靠运行时猜测 |
| 动画 | 确定性函数 `render(t)`，配合总时长即可逐帧复现任意一帧 |
| 自检 | 无头浏览器 + CDP 截图 → 逐段对比 / 捕获 JS 报错 |
| 打包 | 单文件 HTML（内嵌 base64 音频 + 分析数据），无服务器依赖 |
| 依赖 | 运行时**零依赖**；工具链只用 Python(ffmpeg/Pillow) + Node |
